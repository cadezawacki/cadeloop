# Pre-built wheels (in-repo snapshot)

Committed on request as a convenience snapshot — canonical distribution
is the `release.yml` pipeline (PGO + `-v3` variants on tag push), and
these files are NOT that: no PGO, plain `--release` builds of the
commit they ship with.

| wheel | built | verified |
|---|---|---|
| `cadeloop-0.0.1-cp311-cp311-manylinux_2_34_x86_64.whl` | natively on Linux (glibc ≥ 2.34) | ✅ installed into a fresh venv; import + native HTTP serve smoke passed |
| `cadeloop-0.0.1-cp311-cp311-win_amd64.whl` | **cross-compiled from Linux** (`x86_64-pc-windows-gnu`, mingw-w64 GCC 13; `python311.dll` import library generated by pyo3's `generate-import-lib`) | ⚠️ **untested on Windows** — structurally verified only (PE32+ x86-64, links `python311.dll`/`ws2_32.dll`) |

Windows caveats, stated plainly:

- Every prior Windows-validated build of this project was compiled
  **natively with MSVC** on Windows. This wheel is the first mingw-GNU
  build and has never executed.
- It links the legacy `msvcrt.dll` CRT (Debian's mingw-w64 win32
  flavor), not the UCRT that CPython itself uses. The extension passes
  no CRT resources (FILE*, malloc'd memory, fds) across that boundary,
  so this is expected to be benign — but "expected" is not "observed".
- If it misbehaves, build natively instead — on a Windows machine with
  Rust + Python 3.11: `pip install maturin && maturin build --release`
  (or take a wheel from CI / `release.yml`).

Install directly:

```
pip install wheels/cadeloop-0.0.1-cp311-cp311-win_amd64.whl      # Windows
pip install wheels/cadeloop-0.0.1-cp311-cp311-manylinux_2_34_x86_64.whl  # Linux
```
